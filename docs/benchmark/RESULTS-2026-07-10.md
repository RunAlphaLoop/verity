## Metric 2 — stale-citation rate after CDC supersession (target ~0)

**0 stale reads / 200 reads across 100 write→supersede→read cycles = stale-citation rate 0.** 0 consistency timeouts (reads that never saw v2 within 2s).

Each cycle writes fact v1, supersedes it with v2 through the debezium-envelope upsert sequence (L0 episode + deterministic bi-temporal L1 upsert, in-process — no HTTP hop), then immediately reads `current_fact` and BM25 `recall`. Any read returning v1 as current is a stale citation.

| read path | reads | stale | gap p50 | gap p95 | gap p99 |
|---|---|---|---|---|---|
| current_fact | 100 | 0 | 0.42ms | 0.56ms | 0.81ms |
| recall (BM25) | 100 | 0 | 11.38ms | 13.92ms | 18.09ms |

*Gap = elapsed from the v2 write commit to the first read observing v2, including that read's own latency.*

## Metric 4 — scoped-read latency at 1000005 chunks

k=10, 200 queries per case, in-process adapter calls (no HTTP hop; encoder measured separately below).

> **Run conditions:** shared_buffers=1GB, effective_cache_size=15545MB, 0 other active backend(s) at start. In-process adapter calls on the shared dev box (no HTTP hop). Dense-ANN latency at 1M chunks is dominated by whether the index+heap working set fits the engine's page cache; under memory contention from co-tenant workloads the large-footprint cases (10%/50% selectivity) become disk-bound and rise far above the warm single-tenant curve recorded in docs/BENCHMARKS.md. Correctness metrics (1, 2) are unaffected by cache state.
