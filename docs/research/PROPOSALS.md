# Architecture Proposals & Judge Verdicts

> Three architects designed independently under different north stars; a three-judge panel scored them.
> The final spec is the trust-first winner ("Verity") with grafts from the others.

## Proposal (speed-first lens): Membrane — the speed-first, permission-aware shared memory plane for enterprise agents

**Thesis:** Every serious agent-memory system in mid-2026 (Zep ~150-200ms p95, Letta ~300ms, Mem0 ~880ms p50) treats retrieval as a request to a search service; none treats it as an inner-loop primitive. Membrane's bet is that if you (a) keep LLMs, ReBAC engines, and all consolidation strictly off the read path, (b) materialize permissions and entity scopes as precomputed bitmap filters inside a filter-aware ANN index, and (c) resolve supersession deterministically at write time (keyed on entity+field, per MemStrata's 0.95-1.0 accuracy vs 0.20-0.47 for read-time RAG resolution), then 10-30ms p99 scoped recall at tens of millions of items is achievable — an order of magnitude faster than the published state of the art. Speed and safety are the same mechanism: the fastest filter is a precomputed one, and a precomputed, server-enforced scope filter is also the only leak-proof one (CIMemories shows prompting fails at up to 69% leakage). The product is therefore not 'another memory library' but the missing layer nobody OSS ships: source-ACL-inherited, entity-scoped, CDC-fresh shared context, exposed via MCP and a sub-50ms gRPC hot path, with freshness lag (source-change-to-queryable) published as a headline SLO alongside p99 latency.

**Memory Model:** Four layers, hard-separated because they have different write paths, freshness mechanics, and latency profiles. L0 EVIDENCE LOG: append-only, immutable raw episodes — CDC events, webhook payloads, document versions, transcripts, agent observations — each stamped with provenance (source system, writer identity from the MCP EMA/ID-JAG token or A2A Agent Card, trust tier, ingest timestamp). Everything else is derivable and rebuildable from L0; it is also the poisoning-forensics and audit substrate. L1 CANONICAL RECORDS: typed, bi-temporal mirrors of system-of-record objects (Account, Opportunity, Ticket). Updates are DETERMINISTIC upserts keyed on (source, entity_id, field): new value writes a row with valid_from=now, sets valid_to+superseded_by on the old row. Zero LLM involvement — 'opportunity stage changed' supersedes in one keyed write, and freshness lag equals CDC lag (~1-2s for Salesforce Pub/Sub). This is the single biggest speed win over Graphiti/Mem0, which run even structured JSON through LLM extraction. L2 EXTRACTED FACTS: bi-temporal (subject, relation, object) edges produced by ASYNC LLM extraction over unstructured sources only (calls, email, docs), Graphiti-style invalidate-never-delete (invalid_at + reason ∈ {superseded, forgotten, retracted, poisoned}); facts resolving to an L1 entity link to it, and L1 always wins conflicts (system of record outranks conversational inference). Supersession here is keyed on normalized (subject, relation) — never vector similarity, which MemStrata proved is at-chance (0.59 AUROC) for contradiction detection. L3 DERIVED VIEWS: precomputed current-truth projections and per-entity 'briefs' (pinned memory blocks, Letta-style) rebuilt asynchronously by sleep-time workers whenever lineage marks them stale; the read path serves only L3 projections and currently-valid L1/L2 rows. Agent writes land as L0 observations in an untrusted tier with mandatory provenance; Mem0-style ADD/UPDATE/DELETE/NOOP arbitration runs asynchronously and can only produce L2 facts, never mutate L1 (OWASP ASI06 defense by construction). Ranking: similarity × recency-decay × importance applies to episodic/agent-written memory only; L1 facts carry no decay — they are current until superseded.

**Storage Architecture:** Composed, three tiers, one narrow retrieval API — with the hot path IN-PROCESS, because at a 10-30ms p99 budget every network hop matters. SERVING TIER (the speed bet): a Rust serving core embedded in the memory server process holding, per tenant partition: (1) dense ANN via filter-aware HNSW with ACORN-style neighbor-of-neighbor traversal (Qdrant 1.16 proved 97.2% recall at 13.9ms on 5M vectors under 4%-selective filters vs 53% for naive HNSW — filter-awareness, not raw QPS, is the deciding axis); (2) embedded Tantivy for BM25 (Apache 2.0, Datadog-maintained); (3) RoaringBitmap scope masks — per-principal-token, per-entity-tag, per-confidentiality-class posting bitmaps intersected in <1ms before ANN traversal; (4) an in-memory L1 current-truth KV projection for <2ms point lookups of records and pinned briefs. Dense+BM25 run in parallel, RRF-fused. Latency budget: authz-handle lookup 1ms + bitmap intersection <1ms + filtered ANN 5-15ms + BM25 5-10ms (parallel) + fuse/hydrate 2-3ms ⇒ ~15-25ms p99; pinned-brief and record reads ~2-5ms. DURABLE TIER: Postgres as transactional system of record for L0-L3 rows, tenants, lineage, and the changelog the serving tier tails (single-digit-seconds rebuild lag, instant upsert propagation via the change stream); Lance format on object storage (Apache 2.0, Blob v2, time-travel) for multimodal blobs, embedding lineage, and cold history. Tenant isolation is PHYSICAL — partition (index shard + Postgres schema) per tenant, Turbopuffer-style, never a mere filter; filters handle intra-tenant ACL/entity scope. Pragmatic sequencing: the v0.1 serving tier is pgvector 0.8 (iterative scans) + ParadeDB pg_search behind the same Retrieval trait — honest to ~5-10M vectors, one container, ~30-60ms; the native Rust core replaces it in v0.3 and a Qdrant adapter (tiered multitenancy, ACORN) is the supported scale-out profile for >100M-vector fleets. NO graph database dependency — Neo4j is GPLv3, FalkorDB SSPL, Memgraph BSL, Kuzu is dead (Apple acqui-hire) — because the graph ops the read path needs (entity scoping, 1-2 hop expansion, permission edges) are adjacency/bitmap lookups the primary store serves in microseconds. Deep multi-hop KG reasoning is explicitly sacrificed on the hot path; an optional out-of-band Neo4j adapter exists for offline analytics only.

**Ingestion Freshness:** Two-lane, per-connector, running entirely off the read path on Temporal durable workflows (the Dust pattern — freshness pipelines are long-tail failure machines; cron+queues lose). FAST LANE: Salesforce gRPC Pub/Sub CDC (~1-2s delivery, durable replay-ID checkpoints, 72h gap recovery), HubSpot v4 webhooks + journal API, Slack Events, Google Drive changes.watch (auto-renewed ≤7-day channels), Notion webhooks, and a first-class Debezium change-event envelope input (HTTP sink or Kafka topic) so customers' existing DB CDC plugs straight in — we do not build database CDC. TRUTH LANE: cursor-based incremental polls (5-60 min) plus Glean-style full crawls (6h-28d) as the backstop for dropped webhooks, deletions, and ACL drift — push is documented-lossy everywhere, so webhooks are an optimization, never truth. The freshness pipeline splits by data shape: structured field changes upsert L1 deterministically with ZERO embedding work — agent sees the new opportunity amount in <5s end-to-end via record/brief lookup — while text changes flow through stable-chunk-ID, content-hash-diffed incremental re-embedding (CocoIndex-style dataflow with end-to-end lineage; embedding cache keyed on (hash, model, params)), landing in seconds. Derived-memory invalidation: on any source change, synchronously walk lineage to mark dependent L2 facts and L3 briefs STALE (cheap bitmap flip, superseded_at stamped), recompute asynchronously with sleep-time workers; staleness metadata (last_synced_at, is_stale, source_version) is exposed on every retrieval result so agents can reason about it in the interim. ACL changes ride the SAME pipeline as content and rebuild visibility bitmaps within seconds, not Onyx-style sync cycles. Headline product metric: per-connector freshness SLO — p50/p95 source-change-to-queryable — published on a public dashboard next to read latency; nobody in the market reports this.

**Scoping Model:** Three planes, all evaluated before the model ever sees a byte, fail-closed. (1) AUTHORIZATION PLANE: OpenFGA (Apache 2.0, Zanzibar ReBAC) as policy source of truth; connectors ingest source ACLs (Drive/SharePoint/Salesforce sharing) alongside content and write relationship tuples. (2) ENFORCEMENT PLANE — the speed trick: the ReBAC engine is NEVER called on the hot path (AuthZed's own docs: unbounded LookupResources 'will always perform poorly'). Instead, per-item visibility tokens (allowed principals/groups, entity tags, confidentiality class) are materialized into the serving tier's roaring bitmaps, kept fresh by tailing OpenFGA's changelog/Watch stream. At query time: the MCP EMA/ID-JAG token (spec-stable June 2026) yields (user sub, agent azp, act chain) → cached principal-set expansion (short-TTL, 1-2ms) → intersected with the query as a mandatory pre-filter inside ANN traversal. Optional top-k BatchCheck against live OpenFGA (~3-10ms, k≤50) for high-confidentiality classes closes the materialization-staleness window. (3) SCOPE PLANE (beyond ACLs — the customer-A/customer-B problem): sessions open by minting a server-side MemoryScope handle — tenant (physical partition selection), entity_scope (account/deal IDs), purpose class — following AirGapAgent's data-minimization design; a Cerbos-style compiled policy maps (purpose, entity) to retrievable provenance/confidentiality classes for the whole session. The handle is an HMAC-signed scoped credential (Typesense pattern): the filters are bound server-side and physically cannot be widened by agent-supplied parameters or prompt injection — CIMemories proves the model cannot be trusted to withhold, so customer B's pricing never enters a customer-A session's candidate set at all. Scope-soundness is a tested invariant: EVERY read path — search, get-by-id, graph expansion, brief read, MCP resource — passes the same bitmap gate (the documented production leak in the governed-memory literature was an unguarded get-by-id). Every (subject, scope, results) tuple is audit-logged. Cost on the hot path: ~1-2ms cache lookup + sub-ms bitmap intersection — scoping makes queries FASTER (smaller traversal frontier), not slower.

**Api Interop:** Three surfaces, one verb set. (a) MCP server targeting the stateless 2026-07-28 spec from day one — no sessions, server-minted MemoryScope handles for cross-call state, ttlMs/cacheScope hints on brief/record reads, subscriptions/listen for change notifications; consumes EMA/ID-JAG tokens natively for principal identity. This single surface covers Claude, ChatGPT, Gemini, LangGraph, CrewAI, and every MCP-capable client. (b) gRPC + REST hot path for inner-loop calls where MCP transport overhead (~5-15ms) blows the budget — same authz, same scope handles; this is also what the MCP server and ingestion plane call internally. (c) Thin native adapters at each framework's documented plug point: LangGraph BaseStore, Microsoft Agent Framework Memory provider, CrewAI ExternalMemory, Google ADK MemoryService, OpenAI Agents SDK Session backend, Claude Agent SDK memory-tool storage backend — the exact distribution strategy that won Mem0/Zep their footprint, but backed by one shared server. Agent-facing verbs, deliberately minimal: recall (scoped hybrid search, the 10-30ms path, results carry provenance + staleness metadata + citations to L0 evidence), get (record/entity point lookup, ~2-5ms), remember (fast append to L0 — sub-5ms ack; extraction/reconciliation is async), forget (audit-preserving invalidation with compliance semantics), pin/unpin (Letta-style always-in-context entity briefs, CDC-refreshed — the zero-latency answer for the inner loop), subscribe (MCP subscriptions/listen; SSE/webhooks on REST). Agent WRITE-BACK is two-tier by construction: agents can never mutate L1 (system-of-record facts are authoritative and CDC-fed); their writes are append-only L0 observations with mandatory provenance (writer azp/Agent Card, on-behalf-of chain, trust score), asynchronously arbitrated (ADD/UPDATE/DELETE/NOOP) into L2, and trust-tier-weighted at recall. Poisoned-write remediation is surgical: lineage from L0 lets one command invalidate everything derived from a bad episode. Standards posture: ignore AMP/OMP, monitor the W3C AI Agent Memory Interop CG, publish our REST schema as a candidate reference model.

**Multimodal:** Text-canonical at launch, media-aware forever — dictated by both the BYO-key reality (OpenAI, the most common key, still has no multimodal embedder) and the latency lens. Schema separates MediaObject (immutable blob + content hash in Lance on object storage), Representation (versioned derived artifacts: Docling extraction for PDFs/Office, ASR transcripts with speaker turns/timestamps ingested as a format — ASR itself stays out of core, chunk-on-speaker-turn), and Chunk (the retrieval unit: text surface form, named vectors with {model_id, dim, revision} recorded, provenance offsets — page/bbox/audio-ms — and the scoping payload indexed for pre-filtering). Launch pattern is retrieve-by-text, answer-from-pixels: recall returns the chunk plus a signed URI to the original media so a VLM agent answers from the source — most of the multimodal value with zero index changes and zero hot-path cost. Fast-follow: native multimodal single-vector (Cohere embed-v4 / voyage-multimodal-3.5 / Gemini Embedding 2 / self-hosted Jina v4) as an additional named vector on the same chunk row — one vector per page, same HNSW, same latency, closing the ~20-32% retrieval-quality gap of describe-then-embed. Late-interaction (ColQwen3-class) is permanently barred from the default hot path — 1,024 patch vectors per page is 2-3 orders of magnitude too heavy — and offered only as (a) MaxSim rerank over the dense top-k using unindexed stored multivectors or (b) MUVERA fixed-dimensional encodings in the fast index with exact rerank, both opt-in 'high-fidelity documents' mode, cloud-managed by default.

**Language Runtime:** Rust for the entire server — hot path non-negotiably (matches the Qdrant/Tantivy/Lance ecosystem, embeds Tantivy and roaring-rs directly, no GC pauses inside a 10-30ms budget), and Rust for the serving core, scope engine, and MCP/gRPC surfaces. Python for the ingestion/enrichment workers only (connectors, Docling parsing, LLM extraction, embedding calls) running as Temporal workflows — this plane is throughput-bound, not latency-bound, and Python maximizes connector-contributor velocity. Deployment shape, in order of ceremony: (1) `membrane dev` — a single static binary, zero dependencies, embedded SQLite-class storage + in-memory index + bundled web UI for inspecting what agents remember, AND it exposes an MCP endpoint on startup, so any Claude/LangGraph/CrewAI agent has persistent scoped memory within five minutes (the `temporal server start-dev` lesson: docker-compose loses developers, and with 60-80% of new infra now agent-provisioned, the funnel must work when the 'developer' is a coding agent — llms.txt, copy-pasteable MCP config). (2) docker-compose: membrane server + Postgres + Temporal + workers for the full self-hosted stack. (3) Helm for production clusters, with the serving core horizontally scaled per tenant-partition and colocated in-region with the agent runtime (a cross-region hop alone would eat the entire latency budget). Strict API parity between OSS and cloud — conversion is a connection-string change (the LiveKit promise). Not a library/embedded-first design: shared multi-agent memory, server-enforced scoping, and the ingestion plane all require a server; the embedded dev mode exists purely as the adoption wedge.

**Oss Cloud Split:** Apache 2.0, permanently, with a written day-one commitment that the license never changes and shipped OSS features are never removed (the MinIO anti-pattern; Zep's Community Edition retreat is the other cautionary tale — so there is ONE codebase, no OSS-vs-cloud server fork). Apache is also the category norm (Mem0/Graphiti/Letta); AGPL/BSL would make us the licensing outlier and fail conservative enterprise legal review for a component embedded in every agent framework. DCO + trademark, no restrictive CLA games. OSS (feature-complete data plane): the Rust server and serving core, ALL retrieval modes, the full permission/scoping enforcement path including OpenFGA integration and scoped credentials (never paywall the security model — Onyx putting doc-level ACLs behind EE is our differentiation opportunity, and enterprises won't adopt permission enforcement they can't inspect), the bi-temporal L0-L3 schema, MCP/gRPC/REST surfaces and all framework adapters, the connector SDK (protocol MIT, mirroring Airbyte) plus ~10 reference connectors (Salesforce, HubSpot, Google Drive, Slack, Notion, Zendesk, Confluence, Debezium envelope, S3, web crawl — an open connector story is table stakes against Airbyte's 600-connector Context Store push), the eval/leakage benchmark harness, and single-cluster operation. CLOUD (monetize ops and multi-tenancy, not features — the Qdrant/Temporal/Supabase template): the managed control plane (zero-downtime upgrades, shard/tenant tiering and promotion, backups/PITR, autoscaling), the always-on managed connector fleet with OAuth credential management and contractual freshness SLOs, ACL-sync SLAs, multi-region replication and BYOC/hybrid tier, SSO/SAML/SCIM/org-RBAC/audit-log export/compliance reports, managed embeddings + parsing + ASR + late-interaction GPU inference (keyless), freshness/recall observability dashboards, and memory branching for dev/staging environments.

**Mvp Scope:** v0.1 in ~5 weeks, ruthlessly scoped to prove the two headline numbers — scoped-read latency and freshness lag. Week 1-2: Rust server with the Postgres profile (pgvector 0.8 + ParadeDB pg_search behind the Retrieval trait), L0 evidence log + L1 bi-temporal canonical records with deterministic (source, entity_id, field) supersession, physical schema-per-tenant, and the in-process L1 current-truth cache. Week 2-3: scope engine v1 — scoped HMAC MemoryScope handles, mandatory tenant/entity/ACL-token pre-filters compiled into every query (WHERE clauses + B-tree/GIN indexes at this stage), fail-closed on every path including get-by-id; OpenFGA integration stubbed to a static principal-expansion cache. Week 3-4: the six verbs over stateless MCP (2026-07-28 RC) + gRPC, pinned entity briefs refreshed on L1 change, and two connectors that demo the story end-to-end: HubSpot v4 webhooks+journal (fast, no Salesforce license friction) and the Debezium envelope input; a naive polling truth-lane. Week 4-5: `membrane dev` single binary with bundled memory-inspector UI; the open eval harness measuring stale-fact citation rate after a CDC update (target ~0%), cross-entity leakage under adversarial probes (target 0), write-to-visibility p95, and scoped-read p99 — published with reproducible scripts. Demo that sells it: change a deal amount in HubSpot, and a CrewAI agent and a Claude agent both cite the new value in <5s, while a session scoped to customer A provably cannot retrieve customer B's quote. Explicitly deferred: native Rust ANN core (v0.3), Qdrant scale profile, L2 LLM extraction and sleep-time consolidation, Temporal (a simple queue suffices at v0.1), multimodal beyond Docling text extraction, Salesforce Pub/Sub connector, subscriptions/listen.

**Tradeoffs Risks:** Deliberate sacrifices the speed lens demands: (1) No deep KG reasoning on the hot path — multi-hop graph inference, community detection, and rich temporal queries are offline/analytics concerns; we will lose some LongMemEval-style multi-hop benchmark points to Graphiti and accept it (those benchmarks are compromised anyway — 6.4% wrong LoCoMo gold answers, non-reproducing vendor numbers). (2) Materialized visibility bitmaps trade a seconds-wide ACL-staleness window for milliseconds of latency; mitigated by changelog-driven rebuilds and optional top-k live BatchCheck for high-sensitivity classes, but a revoked permission can be visible for a few seconds — this must be documented honestly. (3) Read-time simplicity costs write-time complexity: deterministic supersession requires per-source field mappings and entity resolution; wrong mappings silently corrupt L1, so connector conformance tests are load-bearing. (4) Building our own serving core (v0.3) is the riskiest bet — filter-aware ANN is hard, and if we slip, the Qdrant adapter is the fallback at the cost of a network hop and a weaker differentiation story. (5) Postgres default caps single-deployment scale at ~5-10M vectors and ~30-60ms — below the headline target — meaning our marquee latency claims only hold on the native core; sequencing risk if adopters benchmark v0.1. Market risks: Airbyte Agents' Context Store (600+ connectors) attacks from the integration side and Weaviate Engram from the database side — our moat must be the permission/scope plane, which is genuinely hard to retrofit; MCP's fast-moving spec (stateless RC lands July 28, 2026) could shift again; Salesforce/Glean/Notion could bundle 'good enough' memory into their silos, which is exactly why the vendor-neutral positioning and the open scoped-recall/leakage benchmark (defining the metric the category is judged by) must land early. Finally, the two-language split (Rust core, Python ingestion) taxes a small team; we accept it because the alternative — Python anywhere near the read path — forfeits the entire thesis.

## Proposal (trust-first lens): Verity — a permission-aware, bi-temporal shared context plane for enterprise agents (open-core, Apache-2.0, Rust)

**Thesis:** The agent-memory market has crowded into personalization memory (Mem0, Memobase, Honcho) and agent-managed context (Letta), while the thing enterprises actually need — a shared, always-fresh, permission-inherited context layer over their systems of record — exists only inside closed platforms (Glean, Supermemory, Salesforce Agentforce). Verity's bet is that correctness is the category-defining feature, not recall quality: an agent must NEVER surface customer B's pricing to customer A, NEVER cite a superseded opportunity value, and NEVER trust an unprovenance'd fact — and the research proves none of this can be delegated to the model (CIMemories: up to 69% attribute leakage under prompting; MemStrata: embedding similarity is at-chance, 0.59 AUROC, at detecting contradictions). So every guarantee is architectural and deterministic: ReBAC-derived visibility tokens compiled into the ANN query as mandatory pre-filters (never post-filter, never prompt-level), deterministic keyed supersession for structured records (no LLM in the write path for CRM data), bi-temporal invalidate-never-delete facts with full provenance to immutable evidence, and a scope-soundness invariant enforced on every retrieval path including get-by-id. Speed is the second bet: because the read path contains zero LLM calls and zero live authorization-engine calls (principals are cached, ACLs are materialized), sub-50ms p95 scoped retrieval — 3-10x faster than Zep's published 148-168ms and genuinely usable in an agent's inner loop — falls out of the correctness architecture rather than fighting it. Distribution is MCP-first (stateless 2026-07-28 spec) plus thin adapters into every framework's documented memory plug point, exactly the Mem0/Zep playbook, but multi-tenant and enterprise-authenticated: 'OpenMemory for organizations, with permissions.'

**Memory Model:** A four-layer bi-temporal model where every layer above L0 is a derived, rebuildable projection — the evidence-vs-belief split validated by Eywa, Graphiti, and the Governed Shared Memory paper. L0 EVIDENCE LOG: append-only, immutable raw episodes — CDC events, webhook payloads, document versions, transcripts, agent observations — each stamped with provenance (source system, writer principal, agent identity from the MCP token's sub/azp/act chain, trust tier, ingest timestamp, content hash). Nothing here is ever rewritten; it is the audit log, the poisoning-forensics substrate, and the replay source when extraction improves. L1 CANONICAL RECORDS: typed, versioned mirrors of system-of-record objects (Account, Opportunity, Ticket, Contact) updated by DETERMINISTIC upsert keyed on (source, entity_id, field) with bi-temporal versioning (valid_from/valid_to/superseded_by, plus ingestion time). This is the load-bearing design decision per MemStrata: 'opportunity stage changed' is a keyed write that structurally retires the old value — 0% stale-fact serving vs 15-40% for RAG-style stores — with no LLM, no embedding, no similarity judgment involved. Structured data is NEVER run through LLM extraction (the single biggest error the conversation-memory vendors, including Graphiti's JSON-episode path, make). L2 EXTRACTED FACTS: bi-temporal (subject, relation, object) triples produced by async LLM extraction ONLY over unstructured sources (calls, email, docs, chat), Graphiti-style: contradicting facts set invalid_at with a reason ∈ {superseded, retracted, forgotten, poisoned} — invalidated, never deleted, preserving as-of-time queries. Supersession is keyed on normalized (subject, relation), never on vector similarity. Where a fact's subject entity-resolves to an L1 record, it links to it, and L1 always wins conflicts: the system of record outranks conversational inference. L3 DERIVED VIEWS: precomputed current-truth projections — per-entity pinned summaries (Letta-block-style, attached to agents and updated live by CDC), scope-partitioned indexes, and profile cards — rebuilt asynchronously with lineage back through L2/L1 to L0, so a source change synchronously marks dependents STALE (cheap lineage walk) and recomputes them lazily (expensive LLM calls off the hot path), with staleness metadata (is_stale, source_version, last_synced_at) visible to agents in the interim. Writes from agents are two-tier by trust: Tier-1 facts (CDC-derived) are agent-immutable; Tier-2 agent observations are append-only proposals to L0 carrying mandatory provenance, reconciled asynchronously into L2 via Mem0-style ADD/UPDATE/NOOP arbitration, ranked below Tier-1 at recall, and quarantinable — the OWASP ASI06 memory-poisoning answer, with surgical rollback of everything derived from a poisoned episode via lineage.

**Storage Architecture:** Composed three-tier architecture behind one narrow retrieval API, with pluggable backends at exactly one seam (a Rust storage-adapter trait). NO dedicated graph database — Neo4j is GPLv3, FalkorDB SSPLv1, Memgraph BSL (all license-incompatible with an Apache-2.0 core), and KuzuDB's abandonment (Apple acqui-hire, Oct 2025) shows the embedded-graph risk. The graph operations agent memory actually needs at query time — entity scoping, 1-2 hop relation expansion, permission edges — are cheap adjacency lookups served as rows/payload indexes in the primary store; the bi-temporal knowledge graph is a SCHEMA (Graphiti-compatible concepts: episodes, facts, valid_at/invalid_at), not an engine dependency. SERVING TIER (the <50ms path): one hybrid index holding dense vectors + BM25/sparse + payload-indexed scope metadata, where every record carries tenant_id, entity_ids, acl_tokens, confidentiality_class, trust_tier, valid_from/valid_to, and every query must carry scope filters pushed INTO the index — in-graph/pre-filtering only, never post-filtering (naive HNSW recall collapses to ~53% under selective filters; filter-aware engines hold 97%+). Two reference profiles: DEFAULT = Postgres 17 + pgvector 0.8 (iterative index scans) + pgvectorscale + ParadeDB pg_search for real BM25 — one container, transactional freshness for free, scope filters as indexed WHERE clauses, honest ceiling ~5-10M vectors; SCALE = Qdrant (Apache 2.0) with ACORN filter-aware HNSW (97.2% recall at 13.9ms on 5M vectors under 4%-selective filters; 20-30ms filtered p99 reported at 100M) and tiered multitenancy with zero-downtime tenant promotion. Tenant isolation is PHYSICAL (schema/collection per tenant, Turbopuffer-style namespace discipline), never a mere filter; filters handle intra-tenant ACL and entity scoping. DURABLE TIER: Lance format on object storage (Apache 2.0, Blob encoding, ~100x faster random access than Parquet, native versioning/time-travel) as the multimodal source-of-truth corpus — raw media, transcripts, embedding lineage, re-embedding jobs — feeding the serving tier asynchronously. HOT TIER (optional): Valkey for session/working memory and principal-set cache. How <50ms is achieved: zero LLM calls on the read path, zero live ReBAC calls (materialized ACL tokens + cached principal expansion, 1-2ms), parallel ANN + BM25 + 1-hop adjacency over precomputed L3 current-truth projections (5-20ms filtered ANN on Qdrant-class engines), RRF fusion and composite similarity×recency×trust ranking in Rust (~1ms), single-region colocation with the agent runtime. Pinned entity blocks serve the hottest inner-loop reads in ~5ms as straight key lookups. Milvus, Chroma, and Turbopuffer-style object-storage serving are explicitly rejected for the core (ops weight, scale ceiling, and cold-start cliff/~200ms write commit respectively).

**Ingestion Freshness:** A two-lane, per-connector freshness system running entirely on durable execution (Temporal, following Dust's production pattern — one workflow per change event handling fetch→enrich→chunk→embed→index with retries, rate-limit backpressure, and replay-ID checkpointing). FAST LANE: push events — Salesforce CDC via gRPC Pub/Sub (~1-2s delivery, durable replay-ID persistence, 72-hour gap recovery), HubSpot v4 webhooks + journal API, Slack Events, Notion webhooks, Google Drive changes.watch (with mandatory channel renewal before the 7-day expiry), and Debezium change-event envelopes accepted as a first-class input format so customers with existing Kafka/Debezium infra plug 20+ database connectors in directly. TRUTH LANE: cursor-based incremental polling (5-60 min) plus Glean-style full crawls (6h-28d) as the consistency backstop for dropped webhooks, deletions, and — critically — permission drift; webhooks are documented-lossy everywhere and Notion doesn't even fire on block edits, so push is an optimization, never truth. ACLs sync through the SAME pipeline as content: every connector ingests sharing metadata alongside documents and writes ReBAC tuples, targeting seconds-level permission freshness instead of Onyx-style periodic sync cycles. The freshness decomposition for the flagship SLO ('opportunity updated → agent sees it'): 1-2s CDC event + enrichment fetch + transactional L1 upsert = new value retrievable in <5s via entity lookup with ZERO embedding work, because structured-field changes never wait on an embedding queue; text-field changes trigger chunk-level incremental re-embedding (stable chunk IDs, content-hash diffing, embedding cache keyed on (hash, model, params) — CocoIndex's dataflow-with-lineage design is the reference and a candidate component) completing in seconds. Derived-memory invalidation is the lineage cascade: on any L0/L1 change, synchronously walk lineage to mark dependent L2 facts and L3 summaries STALE with superseded_at timestamps (invalidate-don't-delete), recompute asynchronously sleep-time-style, and expose is_stale/source_version in the retrieval API so agents can reason about it. Per-connector freshness SLOs (p50/p95 event-to-queryable) are published as a headline product metric — nobody in the market does this. Flagship native connectors (owned, not delegated): Salesforce, Google Drive, Slack, Notion, HubSpot, Confluence, Postgres-CDC, generic web crawl; long tail via a Nango adapter; Airbyte relegated to cold backfill.

**Scoping Model:** Three planes, all in the OSS core, all fail-closed. (1) AUTHORIZATION PLANE — OpenFGA (Apache 2.0, Zanzibar-model) as the policy source of truth. Connectors write relationship tuples mirroring source ACLs (Drive/SharePoint/Salesforce sharing models) alongside content, flowing through the same CDC pipeline for seconds-level permission freshness. (2) ENFORCEMENT PLANE — the ReBAC engine is NEVER called on the hot path (AuthZed's own docs: unbounded LookupResources 'will always perform poorly'). Instead, per-item visibility tokens (allowed principals/groups + confidentiality class) are materialized into the serving index, kept fresh via OpenFGA's changelog/Watch stream; at query time the subject — cryptographically identified from the MCP Enterprise-Managed-Authorization / ID-JAG token: user sub + agent azp + act delegation chain — resolves to a short-TTL-cached principal set (1-2ms) attached as a MANDATORY pre-filter inside the filtered-HNSW query. For high-sensitivity confidentiality classes, an optional top-k BatchCheck against live OpenFGA (~3-10ms for k≤50) closes the materialization-staleness window. Budget: 1-2ms principal cache + 5-20ms filtered ANN + optional recheck — comfortably inside 50ms. Items with no visibility tokens return nothing; queries with no resolvable subject return nothing. (3) SCOPE PLANE (beyond ACLs — the customer-A/customer-B problem): every read carries a server-constructed MemoryScope, never caller-optional filters. tenant_id maps to a physical partition. entity_scope is a mandatory filter derived from provenance tags stamped at write time. Purpose binding follows AirGapAgent: a session declares its context (entity + task purpose) ONCE at open; a deterministic Cerbos-style compiled-predicate policy maps that context to the retrievable set of provenance/confidentiality classes and the gate holds for the whole session regardless of what the conversation or an injected prompt asks — CIMemories proves the model cannot be trusted to withhold (69% leakage under prompting), so customer B's pricing never enters a customer-A-scoped context window, period. Cross-entity analytics requires opening an explicitly different, audited scope. The Governed-Shared-Memory 'scope-soundness' invariant is enforced in the storage engine on EVERY retrieval path — search, get-by-id, graph expansion, pinned-block read, MCP resource read — because the documented production leak came through the unguarded get-by-id path. Agents inherit the intersection of their data sources' access by default (Dust's rule). Every (subject, scope, results) tuple is audit-logged. Enforcement mechanism for credentials: Typesense-style HMAC-scoped tokens binding non-overridable tenant/entity filters server-side.

**Api Interop:** Three layers. (a) MCP SERVER, first-class, targeting the stateless 2026-07-28 spec from day one: no session affinity, server-minted handles for multi-step retrieval, ttlMs/cacheScope hints on entity reads, subscriptions/listen for change notifications, and native consumption of EMA/ID-JAG tokens so the (user, agent, on-behalf-of) tuple is the authorization subject. Tool surface is deliberately tiny — memory.recall (scoped hybrid search), memory.remember (fast append to L0; extraction async), memory.forget (audited invalidation with compliance semantics), memory.pin/unpin (Letta-style always-in-context entity blocks, CDC-live), memory.subscribe — with all scope parameters required in the signature but enforced server-side from the token, never from agent-supplied values. (b) REST + gRPC SUBSTRATE: the thing the MCP server itself calls — gRPC for the sub-50ms inner-loop hot path (MCP transport overhead matters at this budget), REST for ingestion, admin, bulk ops, webhooks/SSE mirroring subscriptions for non-MCP consumers. The wire protocol is separately MIT-licensed (Airbyte's move) so third parties implement clients freely. (c) THIN NATIVE ADAPTERS into every framework's documented plug point: LangGraph BaseStore (hierarchical namespaces map 1:1 onto our tenant/entity paths), Microsoft Agent Framework Memory provider, CrewAI ExternalMemory, Google ADK MemoryService, OpenAI Agents SDK Session backend, Claude Agent SDK memory-tool storage backend — the exact distribution playbook Mem0/Zep proved. Agent write-back: two-tier trust as described in the memory model — Tier-1 CDC facts are agent-immutable; Tier-2 agent observations are append-only L0 proposals with mandatory provenance (writer azp, A2A-compatible agent identity, source, timestamps, derivation chain), reconciled asynchronously with ADD/UPDATE/NOOP arbitration, bi-temporally superseded, trust-ranked at recall, and quarantined when originating from low-trust sources (web, inbound email). Standards posture: ignore AMP/OMP, monitor the W3C AI Agent Memory Interop CG, position our REST schema as a candidate reference implementation.

**Multimodal:** Text-canonical, media-aware at launch — dictated by the BYO-key reality that OpenAI (the key most users hold) still has no multimodal embedder. Every memory item carries (a) a text surface form — Docling-parsed document text, ASR transcripts ingested with speaker turns/timestamps (ASR itself stays OUT of core; accept transcripts, chunk on speaker turns, store audio-URI + time offsets so agents cite who-said-what-when), VLM-generated descriptions for images, templated serialization for structured records — embedded with the user's BYO text model; plus (b) a MediaObject pointer (storage URI in the Lance tier, content hash, MIME, chunk-level provenance: page, bounding box, audio ms range, speaker). Retrieve-by-text, answer-from-pixels: the original media is handed to the VLM agent at generation time, capturing most multimodal value with zero index changes. Schema separates three layers — immutable MediaObject, versioned Representation (extraction/transcript/caption, stamped with the pipeline that produced it), and Chunk (retrieval unit with named vectors + the scoping payload) — so CDC updates mean new Representations, chunk upserts by stable ID, and hash-idempotent re-ingestion. FAST-FOLLOW: native multimodal single-vector via an embedder capability flag — Cohere embed-v4, voyage-multimodal-3.5, Gemini Embedding 2, or self-hosted Jina v4 for keyless OSS users — stored as an additional named vector on the same chunk row (never mix models/dims in one index; {model_id, dim, revision} recorded per embedding for lazy re-embedding), since direct visual embedding beats describe-then-embed by ~20-32% on visually rich content. LATER, opt-in only: late-interaction 'high-fidelity documents' mode via MUVERA fixed-dimensional encodings in the fast index with exact MaxSim rerank over unindexed stored multivectors (Qdrant pattern) — never the default, as ~1,024 patch vectors/page is irreconcilable with the inner-loop latency budget.

**Language Runtime:** Rust for the core server — the serving hot path (scope-filter compilation, principal cache, RRF fusion, ranking), the storage-adapter trait, the MCP/gRPC/REST surfaces, and embedded Tantivy if lexical search is later internalized; this matches the Qdrant/Lance/Tantivy ecosystem the architecture composes. Python for the ingestion/enrichment plane (connector SDK, Temporal workflows, LLM extraction, Docling parsing) where the ecosystem lives and latency doesn't matter. Deployment shape, copying Temporal's explicit lesson that docker-compose loses developers: a SINGLE STATIC BINARY with `verity dev` — zero dependencies, embedded SQLite-class storage, in-memory index, bundled web UI for inspecting what agents remember, and an MCP endpoint exposed on startup, so within five minutes any Claude/LangGraph/CrewAI agent has persistent scoped memory. docker-compose brings the full stack (Postgres/Qdrant profile, Temporal, connector workers) as step two; Helm for production. Server, not library — shared multi-agent memory and permission enforcement both require a server; the embedded dev mode exists for the funnel, not the architecture. Strict API parity between self-hosted and cloud (LiveKit's promise): conversion is a connection-string change. The funnel is designed for AI builders as much as humans — MCP-native provisioning, llms.txt, copy-pasteable docs — since Supabase (60%+ of new DBs from AI tools) and Neon (80% agent-provisioned) show agents are the largest acquisition channel.

**Oss Cloud Split:** Apache 2.0 for everything in the repo, permanently, with a written day-one commitment that the license never changes and shipped OSS features are never removed (the MinIO anti-pattern), DCO + trademark rather than CLA-heavy control. Apache is the category norm (Mem0, Graphiti, Letta, Cognee) and AGPL/BSL would make us the licensing outlier while blocking the embedded-in-every-framework adoption a memory layer needs; the fork-risk mitigation is a proprietary control plane, not copyleft (the Valkey/OpenTofu lesson). OSS, in full: the engine, both storage profiles, the ENTIRE permission/scoping/enforcement path (gating the security model is the Onyx-EE mistake and would kill trust in exactly our differentiator — Supabase never gated RLS), the bi-temporal schema, the MCP server, all SDKs/adapters, the connector SDK, ~10-15 reference connectors including the flagships (Salesforce, Drive, Slack, Notion, HubSpot, Confluence, Postgres-CDC, web crawl — Airbyte's 600-connector Context Store push makes an open connector story table stakes), the eval harness, and single-cluster operation. **Mvp Scope:** v0.1 in ~5 weeks proves the two wedges — scoped recall and live supersession — end to end, deliberately cutting everything else. Ships: (1) the Rust server on the Postgres profile only (pgvector + ParadeDB pg_search in one container; Qdrant adapter deferred, but the storage trait defined now); (2) L0 evidence log + L1 deterministic keyed bi-temporal records + chunk store with text embeddings via BYO OpenAI/Cohere/local key — L2 LLM fact extraction and L3 summaries deferred; (3) the full enforcement path in miniature: OpenFGA tuples, materialized visibility tokens, cached principal expansion, mandatory pre-filters on every path including get-by-id, HMAC-scoped session tokens, fail-closed defaults, audit log; (4) two connectors that tell the whole story — Salesforce (Pub/Sub CDC, opportunity-update-to-queryable <5s, ACL ingestion) and Google Drive (changes.watch + renewal + polling backstop, Docling parsing, Drive-ACL inheritance) — on Temporal workflows; (5) the MCP server (recall/remember/forget/pin, stateless 2026-07-28 target) plus REST, plus one framework adapter (LangGraph BaseStore); (6) `verity dev` single-binary quickstart with the memory-inspector web UI; (7) the v0 of the open eval harness measuring the three numbers nobody else publishes: stale-fact citation rate after a CDC update (target ~0%), cross-entity/tenant leakage under adversarial probes (target 0), and p50/p95 event-to-queryable freshness lag — plus a published latency-vs-corpus-size curve targeting <50ms p95 scoped recall at 1M chunks. **Tradeoffs Risks:** (1) Latency claim risk: 10-30ms is unproven at 100M-item scale — ACORN numbers are vendor benchmarks at 5M vectors, and our composite query (ANN + BM25 + adjacency + fusion) could stack to 50-80ms under load; mitigation is the pinned-block fast path (pure KV, ~5ms) for inner-loop reads and publishing honest curves rather than aspirational claims. (2) Materialized-ACL staleness window: seconds can elapse between a source permission revocation and index-token update — a real (if small) leakage window we mitigate with changelog-driven sync, the optional top-k live BatchCheck for high-sensitivity classes, and fail-closed defaults; enterprises must be told the SLO, not sold 'instant.' (3) Composed-system complexity: Postgres + OpenFGA + Temporal + object storage is a lot of moving parts for a 'memory layer' — the single-binary dev mode masks this for the funnel, but production self-hosting is genuinely heavier than pip-install Mem0, and that friction is partly load-bearing for cloud conversion (an honest but real tension). (4) Purpose binding constrains legitimate use: AirGap-style session scoping will frustrate agents doing legitimate cross-account work; the audited cross-entity scope is the answer but adds ceremony, and product taste in scope granularity will make or break adoption. (5) Competitive convergence: Airbyte Agents (600 connectors + Context Store), Weaviate Engram, and Cognee are all one roadmap item away from permission-aware retrieval; our moat is that ACL inheritance + deterministic supersession are the hardest things to retrofit, but the window is 12-18 months. (6) Deterministic supersession only covers keyed data: L2 conversational facts still depend on LLM extraction quality (up to 30% format-failure rates on weak backbones), so unstructured-source correctness is probabilistic no matter what we claim — the trust-tier ranking makes this visible rather than solving it. (7) MCP 2026-07-28 is a release candidate; building stateless-first is right, but spec drift before final publication could force interface rework. (8) Open-core discipline risk: the managed-connector line will tempt future feature-gating of connectors themselves; the public never-remove commitment must be structurally binding (e.g., connectors in a separately-governed repo) or we become the MinIO cautionary tale we cite.

## Proposal (adoption-first lens): Hivemind

**Thesis:** Every serious agent-memory player (Mem0, Zep, Letta, Cognee) is fighting over conversational/personalization memory while the actual enterprise problem — agents need permission-aware, always-fresh context from systems of record, shared across frameworks — sits unclaimed. Hivemind is the "open-source Glean-for-agents": a single Apache-2.0 Rust binary that syncs CRMs/docs/tickets/web into a bi-temporal memory store with source-ACL-inherited, entity-scoped retrieval, served over MCP (2026-07-28 stateless spec) and gRPC at sub-50ms p95 with zero LLM calls on the read path. The adoption bet: `docker run hivemind` (or `hivemind dev`, one static binary with embedded storage) to first scoped recall in under 5 minutes, MCP-first so every framework works day one, and a moat built on the two things hardest to retrofit and absent from all OSS competitors — ReBAC permission enforcement compiled into the ANN query, and CDC/webhook freshness with deterministic supersession. Nobody publishes low-tens-of-ms numbers (Zep's ~150-200ms p95 is the current bar), and nobody measures permission leakage; Hivemind publishes both and defines the "scoped recall" benchmark that names the category.

**Memory Model:** Four layers, per the MemStrata/Eywa/Graphiti-validated science, with structural (never LLM/similarity-based) supersession. L0 EVIDENCE LOG: append-only, immutable raw episodes — CDC events, webhook payloads, document versions, transcripts, agent observations — each stamped with provenance (source system, writer identity via MCP EMA/ID-JAG token, trust tier, ingest time). Everything else is derivable/replayable from L0; this is also the poisoning-forensics and audit layer. L1 ENTITY RECORDS: typed, versioned mirrors of system-of-record objects (Account, Contact, Opportunity, Ticket, Page). A CRM row stays a row. Updates are deterministic upserts keyed on (source, entity_id, field) with bi-temporal versioning (valid_from/valid_to/superseded_by) — "opportunity stage changed" is a keyed write that retires the old value with zero LLM involvement (MemStrata: deterministic supersession serves stale facts ~0% vs 15-40% for RAG; embedding similarity is 0.59 AUROC at detecting contradictions, so this can never be similarity-based). L2 EXTRACTED FACTS: Graphiti-schema bi-temporal (subject, relation, object) triples produced by async LLM extraction ONLY over unstructured sources (conversations, docs, email); contradicting facts get invalid_at set (invalidate-never-delete, reason ∈ {superseded, forgotten, retracted, poisoned}); facts resolving to an L1 entity link to it, and L1 always outranks L2 in conflicts (system of record beats conversational inference). L3 DERIVED VIEWS: precomputed current-truth projections, entity profile cards, and pinnable summary blocks (Letta-style memory blocks, updated live by CDC) rebuilt asynchronously with lineage back to L0 — on source change, dependents are synchronously marked STALE (cheap) and recomputed async (expensive), with staleness metadata (is_stale, last_synced_at, source_version) visible in every retrieval response. Writes are two-tier trust: Tier-1 CDC-derived facts are authoritative and agent-immutable; Tier-2 agent-written observations are append-only proposals with mandatory provenance, reconciled asynchronously (Mem0-style ADD/UPDATE/DELETE/NOOP arbitration off the hot path), and ranked below Tier-1 at recall — the OWASP ASI06 memory-poisoning defense built in, not bolted on.

**Storage Architecture:** One Rust server, three tiers, pluggable at exactly one seam (a StorageAdapter trait), and — deliberately — NO graph database dependency (Neo4j GPLv3, FalkorDB SSPL, Memgraph BSL are all license-hostile; KuzuDB's Apple acqui-hire death is the cautionary tale; the graph ops we need at query time — entity scoping, 1-2 hop expansion, permission edges — are cheap adjacency lookups over rows/payloads). SERVING TIER (the <50ms path): DEFAULT PROFILE = Postgres with pgvector 0.8 (iterative index scans fix filtered-recall collapse) + pgvectorscale + ParadeDB pg_search for BM25 — one container, transactional freshness for free, scope filters as indexed WHERE clauses, honest ceiling ~5-10M vectors; this is the adoption profile (Cognee/Memobase proved Postgres-default maximizes OSS uptake, and `hivemind dev` mode embeds SQLite+usearch+Tantivy for zero-dependency laptop use). SCALE PROFILE = Qdrant (Apache 2.0): ACORN filter-aware HNSW (97.2% recall at 13.9ms on 5M vectors under 4%-selective filters — exactly our workload, since every query carries mandatory tenant/scope/ACL filters), tiered multitenancy with zero-downtime tenant promotion, native sparse vectors for hybrid fusion, 20-30ms filtered p99 reported at 100M vectors. Filters are always pushed INTO the index (in-graph/pre-filtering); post-filtering engines are disqualified because post-filter breaks both latency and the permission guarantee. Tenant isolation is physical (collection/schema per tenant); entity/ACL scoping is filter-based within the tenant partition (Turbopuffer's cold-namespace cliff shows per-entity micro-partitions would be too cold). DURABLE TIER: Lance format on object storage (Apache 2.0, Blob encoding, versioning/time-travel) as the multimodal source-of-truth corpus — raw media, transcripts, embedding lineage — feeding the serving tier asynchronously. HOT PATH MECHANICS for 10-30ms: zero LLM calls at read time, parallel ANN + BM25 + 1-2 hop adjacency over precomputed L3 projections, subject→principal-set expansion served from a short-TTL in-process cache (1-2ms), scope filters precompiled into the query, RRF fusion, composite similarity×recency×importance ranking applied only to episodic memory (L1 facts don't decay — current until superseded). Latency budget: principal cache 1-2ms + filtered hybrid search 5-20ms + fusion/rank 2-5ms. Publish latency-vs-scale curves; Zep's 150-200ms p95 at 100M nodes is the bar to beat publicly.

**Ingestion Freshness:** Two-lane, per-connector freshness (the Glean pattern, made open source): a PUSH LANE — Salesforce CDC via gRPC Pub/Sub (~1-2s event delivery, durable replay-ID checkpointing, 72h gap recovery), HubSpot v4 webhooks + journal API, Slack Events, Google Drive changes.watch (with mandatory channel-renewal handling), Notion webhooks, and first-class acceptance of Debezium change-event envelopes (Kafka topic or Debezium Server HTTP sink) so customers with existing CDC infra inherit 20+ database connectors for free — and a TRUTH LANE of cursor-based incremental polling (5-60 min) plus Glean-style full crawls (6h-28d) that reconcile dropped webhooks, catch deletions, and sync permission drift. Webhooks are an optimization, never truth. The entire ingest plane runs on durable execution (Temporal, following Dust's production pattern): one workflow per change event doing fetch → enrich → chunk → embed → index with retries, rate-limit backpressure, and prioritized crawling (hot entities first). Structured field changes bypass embedding entirely — a deterministic L1 upsert makes "opportunity updated → agent sees new value" a <5s path; text changes use stable chunk IDs + content-hash diffing + an embedding cache keyed on (hash, model, params) so only changed chunks re-embed (CocoIndex-style incremental dataflow with end-to-end lineage, built in from day one because lineage is brutal to retrofit). Derived-memory invalidation: on source change, walk lineage to mark dependent L2/L3 rows stale synchronously, recompute async, expose staleness in the API. Ships: (1) the Rust server with `hivemind dev` single-binary mode (embedded SQLite + usearch + Tantivy) and the Postgres/pgvector+pg_search production profile behind the StorageAdapter trait — no Qdrant profile yet; (2) L0 evidence log + L1 deterministic bi-temporal entity records + basic chunk/vector store with content-hash incremental re-embedding — L2 LLM fact extraction and L3 derived views deferred; (3) scoping: physical tenant partitions, mandatory entity_scope filters, HMAC scoped credentials, materialized visibility tokens with fail-closed pre-filtering, and OpenFGA embedded for principal expansion — full connector ACL inheritance lands with each connector; (4) MCP server (stateless 2026-07-28 spec) with recall/remember/forget/pin + REST/gRPC hot path; (5) TWO connectors that demo the story end-to-end: Salesforce (Pub/Sub CDC, <5s field-change-to-queryable, opportunity ACLs) and Notion (webhooks + polling backstop) plus generic webhook/Debezium-envelope ingestion; (6) the web UI showing what an agent can see under a given scope — the demo is "update an opportunity in Salesforce, watch agent A see it in 5 seconds, watch agent B (scoped to another account) never see it"; (7) v0 of the open scoped-recall benchmark: leakage rate under adversarial probes, stale-fact citation rate after CDC update, event-to-queryable lag, p95 latency — published with reproducible harness. Explicitly out of v0.1: multimodal beyond Docling text extraction, LangGraph/CrewAI adapters (fast-follow v0.2), Temporal (v0.1 uses an internal retry queue; Temporal arrives with the connector fleet in v0.3), Qdrant scale profile (v0.3).

**Tradeoffs Risks:** (1) Composed-not-monolithic: choosing Postgres-default + Qdrant-scale over building our own index gets us to market fast but means our latency ceiling is our backends' — if ACORN-style filtered ANN regresses under our exact ACL-token cardinality, the 10-30ms stretch target slips to ~30-50ms; mitigation is the adapter seam and a possible future internalized Rust index (usearch+Tantivy already power dev mode). (2) Materialized visibility tokens trade a permission-staleness window (seconds, bounded by the OpenFGA Watch stream) for hot-path speed; the top-k BatchCheck option covers high-sensitivity data, but a revoked-access-still-visible-for-3-seconds incident is a real reputational risk — we must publish the staleness SLO honestly. (3) No graph database means deep multi-hop reasoning (3+ hops, community detection) is out of scope at query time; Cognee/Graphiti will beat us on graph-heavy benchmarks — acceptable, because our category-defining benchmark is leakage/freshness/latency, but it cedes some GraphRAG mindshare. (4) Connector maintenance is a treadmill (Airbyte has 600; we ship 8) and Airbyte's Context Store pivot is the scariest competitor — a data-integration incumbent adding memory beats a memory startup adding integration on connector count; our counter is permission inheritance + sub-minute freshness + sub-50ms serving, which batch-oriented Airbyte architecturally cannot match, but we must win the flagship-connector quality war, not the quantity war. (5) Deterministic supersession only works when sources have authoritative IDs; messy sources (email threads, web pages) fall back to LLM extraction with its 5-30% error rates — we inherit that quality problem for unstructured content like everyone else. (6) Rust core narrows the contributor pool vs Python/TypeScript (partially offset by Python workers and SDKs being the main contribution surface). (7) Open-core discipline risk: the pressure to paywall the permission plane or a hot connector will be constant; the day-one written covenant is a bet that trust compounds faster than short-term revenue — Zep and MinIO show what breaking it costs. (8) MCP 2026-07-28 is still an RC at design time; if final publication slips or changes handle semantics we carry a small rework, hedged by the gRPC/REST substrate being the real interface.

### Judge 3: Security & compliance architect
**Winner:** Proposal 2: Verity
- Proposal 1: Membrane (speed lens): **7/10** — The enforcement architecture is genuinely leak-resistant by construction: server-minted HMAC MemoryScope handles that agent-supplied parameters cannot widen, mandatory pre-filters compiled into ANN traversal (never post-filter), fail-closed on every path including get-by-id, physical tenant partitioning, and the correct insight that out-of-scope data never entering the candidate set is the ONLY defense that survives prompt injection (correctly citing CIMemories-style evidence that prompt-level withholding fails). So the hardest and most differentiating security claim — ACL inheritance from systems of record — is unproven at launch, and the security model would be evaluated on a mock. (2) The v0.3 custom Rust filter-aware ANN core puts the leak-prevention mechanism (bitmap intersection inside index traversal) inside brand-new, hardest-to-write code; a filter bug in a homegrown ANN index IS a cross-customer leak, and it's the least auditable component in the stack. - Proposal 2: Verity (trust lens): **9/10** — This is the proposal a security review would actually pass. Correctness-as-thesis means the guarantees are architectural and deterministic, and — critically — the MVP proves the FULL enforcement path end-to-end: real OpenFGA tuples, materialized visibility tokens, cached principal expansion, mandatory pre-filters on every path including get-by-id (the documented real-world leak vector), HMAC scoped session tokens, fail-closed defaults, audit log of every (subject, scope, results) tuple — against the two connectors where ACL inheritance is genuinely hard (Salesforce sharing model, Google Drive ACLs). Purpose binding at session-open (AirGapAgent pattern) with cross-entity access requiring an explicitly different, audited scope is exactly the customer-A/customer-B answer: the injected prompt can ask for anything, but customer B's pricing never enters the candidate set. Two-tier trust with quarantinable low-trust writes and lineage rollback addresses memory poisoning. The risk register is the most honest of the three: it names the ACL-staleness window as an SLO to be disclosed, not hidden ('enterprises must be told the SLO, not sold instant'), names LLM-extraction error rates on L2 as irreducibly probabilistic and makes that visible via trust-tier ranking rather than claiming it solved. Keeping the entire security/enforcement path Apache-2.0 (inspectable) is the right call for enterprise trust — enterprises will not run permission enforcement they can't audit. Composing on battle-tested engines (pgvector/Qdrant/OpenFGA) rather than a novel index keeps the leak-critical filter path in widely-reviewed code. **Fatal:** None disqualifying. Residual gaps a reviewer would still probe: (1) multi-entity content — a doc or call transcript mentioning both customer A and B gets chunk-level entity tags at write time, and the proposal never specifies the policy (must be deny-by-default / intersection, not union); (2) L3 derived views and pinned summaries aggregate across sources, and scope inheritance for derived artifacts (a brief must carry the intersection of its lineage's scopes) is implied by lineage but not stated as an enforced invariant; (3) the seconds-wide revocation window is real — needs an event-driven fail-closed tombstone on ACL-revoke events, not just changelog-driven rebuild; (4) connector ACL-mapping fidelity (Salesforce territory hierarchies, implicit sharing) is the silent-failure mode — conformance tests for ACL mapping need to be as load-bearing as the ones P1 demands for field mapping.
- Proposal 3: Hivemind (adoption lens): **8/10** — Two ideas here are disproportionately valuable to passing a security review. First, embedding OpenFGA in the single binary (library/sidecar, not a separate install) removes the most likely enterprise misconfiguration: a memory layer whose authorization engine is optional or separately deployed will be run without it. Second, the web UI showing 'what an agent can see under a given scope' is a first-class audit artifact — it turns the abstract scoping model into something a security reviewer and a compliance auditor can interactively verify, and none of the other proposals ship it. The MVP includes Salesforce with opportunity ACLs, materialized visibility tokens, HMAC credentials, and fail-closed pre-filtering, so ACL inheritance is at least partially exercised at launch. Publishing the leakage-under-adversarial-probes benchmark as the category-defining metric aligns commercial incentives with security outcomes. Otherwise shares the same sound enforcement core (server-side scope handles, pre-filtering, physical tenant isolation, scope-soundness on every path). **Fatal:** Not disqualifying, but: (1) the adoption lens creates TWO enforcement implementations — the embedded dev-mode stack (SQLite + usearch + Tantivy) and the Postgres/Qdrant production stack — and both must uphold the scope-soundness invariant identically; divergence between them is a latent leak, and the proposal doesn't commit to a shared enforcement layer or a cross-profile leakage test matrix. (2) 'Full connector ACL inheritance lands with each connector' is a schedule-shaped promise, i.e., the security guarantee's completeness depends on the connector roadmap, and the 5-minute-wow priority will pressure connector ACL fidelity (the hard 20%) behind connector count. (3) Notion as the second MVP connector exercises freshness, not permissions — Drive (P2's choice) is the harder, better ACL proof. (4) The 'revoked-access-visible-for-3-seconds' risk is acknowledged reputationally but not mitigated with an event-driven fail-closed path.

**Grafts:** From Hivemind (P3): (1) Embed/bundle OpenFGA inside the server binary rather than requiring a separate deployment — the authorization plane must be impossible to skip, because the most common enterprise failure mode is a correctly-designed authz component that isn't wired up. (2) The scope-inspection web UI ('show me exactly what this agent can retrieve under this MemoryScope') shipped in OSS — it is the single best artifact for passing a security review and for internal red-teaming, and it makes the 0-leakage benchmark demonstrable rather than asserted. (3) The category-defining public 'scoped recall' leakage benchmark with reproducible adversarial probes — whoever defines the metric wins the trust narrative. From Membrane (P1): (4) Connector conformance tests as load-bearing infrastructure — extend P1's field-mapping conformance idea explicitly to ACL-mapping conformance per connector (Salesforce implicit sharing, territory hierarchies, Drive inherited folder ACLs), since silent ACL-mapping errors are the most likely real-world leak. (5) The 'scope-soundness as a TESTED invariant' framing — a CI gate that fuzzes every read path (search, get-by-id, adjacency expansion, pinned-brief read, MCP resource read) against scope handles, not just a design principle. (6) Per-item confidentiality classes with mandatory (not optional) top-k live BatchCheck for the highest class — pricing/quotes should default into that class, directly closing the staleness window on exactly the customer-A/customer-B data. (7) The Debezium change-event envelope as a first-class input. Grafts required from neither proposal (gaps all three share, must be added to the winner): deny-by-default/intersection semantics for multi-entity chunks (a doc mentioning customers A and B is retrievable only in a scope covering both, or in neither); an enforced scope-inheritance invariant for L3 derived views and pinned briefs (a derived artifact carries the intersection of its lineage's scopes and is invalidated when any ancestor's scope narrows); and an event-driven fail-closed tombstone on ACL-revocation events that hides items immediately, ahead of the asynchronous bitmap rebuild.

**Rationale:** All three proposals converge on the same fundamentally correct security architecture — server-minted, HMAC-bound scope handles; ACLs materialized as mandatory pre-filters inside the index; physical tenant partitioning; fail-closed on every read path; out-of-scope data never entering the model's context. That architecture genuinely defeats adversarial prompts, because prompt injection can only manipulate the model, and the model never possesses customer B's data in a customer-A session; the leakage question reduces to non-prompt channels (ACL staleness, tagging fidelity, derived-view aggregation, enforcement-path coverage). The differentiator is therefore not the design on paper but what is PROVEN, what is HONEST, and where the org's incentives point. Verity wins on all three: its MVP exercises the complete enforcement chain against the two hardest real ACL models (Salesforce, Drive) rather than stubbing authorization (Membrane) or deferring ACL inheritance to the connector roadmap (Hivemind); its risk register discloses the revocation-staleness window as an SLO to be told to customers, which is precisely the posture that passes an enterprise security review (reviewers forgive bounded, disclosed windows; they fail vendors who claim 'instant'); and its trust-lens thesis means latency and adoption pressure cannot quietly erode the security mechanism, whereas Membrane's 10-30ms headline and Hivemind's 5-minute wow both create structural incentives to widen caches, skip live rechecks, or ship connectors without ACL fidelity. Membrane's homegrown filter-aware ANN core is the deciding negative for a security lens: it relocates the leak-prevention mechanism into the newest, least-audited code in the stack, where a traversal bug is indistinguishable from a breach. Hivemind is a close second and contributes the two best grafts (embedded OpenFGA, the scope-inspection UI), but its dual enforcement implementations (dev vs production profiles) and roadmap-dependent ACL completeness are exactly the kind of findings a pentest report leads with. With the named grafts applied — especially multi-entity intersection semantics, derived-view scope inheritance, and event-driven revocation tombstones, which no proposal fully covers — Verity is an architecture I would expect to clear a serious enterprise security review, with the residual risk honestly reduced to connector ACL-mapping fidelity and bounded, disclosed staleness windows.
